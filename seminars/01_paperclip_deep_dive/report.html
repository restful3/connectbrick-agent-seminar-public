    1. Weekly Digest — 에이전트 생태계 2026 5월

    1줄 thesis — 능력 경쟁은 끝났고, 코디네이션이 새 병목 이다.

    1.1 왜 지금 "에이전트 회사" 인가 — 큰 그림

    2024년 말부터 2025년까지의 흐름은 "모델 한 개의 능력을 어디까지 끌어올릴 수 있나" 의 경쟁이었다. Claude 4 / GPT-5o / Gemini 2.5 세대를 지나면서 단일 호출의 reasoning · tool use 품질이 충분히 올라간 결과, 병목은 모델 한 개의 IQ가 아니라 "여러 호출을 어떻게 조정하고, 어디까지 자율 실행을 맡길 것인가" 의 코디네이션 비용 으로 이동했다.

    LangChain의 State of Agent Engineering 2025/2026 설문(1,340명, 2025-11~12 수집)에서 응답자의 57%가 에이전트를 production에 투입 했다고 답했고, 1만 명 이상 대기업으로 좁히면 67%가 production 단계 다.[^langchain]

    이 맥락에서 "한 사람 + N개 에이전트로 운영되는 회사" 담론이 단순 밈을 넘어 실제 도구 카테고리로 굳어졌다. 2026-03-04 공개된 오픈소스 Paperclip 은 6주 만에 GitHub 53,000+ stars를 모았는데, 핵심은 "에이전트를 더 똑똑하게 만든다" 가 아니라 "에이전트들에게 직책·예산·승인 라인을 부여하고 조직도(org chart) 위에서 운영한다" 는 발상이다.[^paperclip-gh][^jimmysong] Gartner는 multi-agent 시스템 관련 문의가 2024 Q1 → 2025 Q2 +1,445% 증가 했다고 보고했고[^mlmastery], SK AX도 "2026년부터 10개 이상 에이전트가 협업하는 시스템이 보편화" 라는 국내 전망을 내놓았다.[^skax-multi] Paperclip은 이 흐름의 가장 가시적인 산출물 중 하나로 보는 것이 적절하다.

    1.2 메타 트렌드 5개 — 깊이판

    본 절은 사전 디지스트(digest.html)의 5 트렌드를 각각 한 단락 더 풀어서 정리한다. 디지스트가 30분 안에 훑는 사전 자료라면, 본 절은 세미나 후 다시 펴서 인용·근거를 확인하는 용도다.

    1.2.1 멀티에이전트 프레임워크의 패러다임 분화

    2025년까지 "에이전트 프레임워크" 라는 한 덩어리로 묶여 있던 영역이 2026년에는 패러다임별로 분명히 갈렸다. LangGraph (상태 그래프 + HITL 체크포인트, v0.4) / CrewAI (역할·프로세스 기반 crew, 엔터프라이즈 관측성 추가) / AutoGen v2 / AG2 (대화형 GroupChat, 1.0 GA) / OpenAI Agents SDK / Google ADK / Deep Agents (Anthropic 계열, skill 중심) 등이 각자 다른 멘탈 모델을 표방한다.[^pecollective][^turing]

    왜 중요한가 — "어떤 프레임워크를 쓰지?" 가 더 이상 취향 문제가 아니라 "우리 워크플로의 모양이 그래프냐, 역할극이냐, 대화냐, 회사냐" 라는 질문이 됐다. 본 리포트 2장에서 이 4분류를 본격적으로 다룬다.

    1.2.2 MCP(Model Context Protocol)의 사실상 표준화

    2024년 11월 Anthropic이 발표한 MCP가 18개월 만에 에이전트-도구 인터페이스의 사실상 표준 이 됐다. 공개 MCP 서버 레지스트리는 2025 Q1 1,200개 → 2026년 4월 9,400개+ 로 늘었고 (월간 +18% 성장), Claude / ChatGPT / Gemini / Cursor / Windsurf / Zed / JetBrains AI / Vercel AI SDK / OpenAI Agents SDK가 모두 MCP를 네이티브로 채택했다.[^digitalapplied][^mcp-roadmap]

    왜 중요한가 — 2025년까지의 통합은 "벤더별 plugin / function calling 스펙을 일일이 맞춰 짜기" 였는데, MCP 이후로는 "한 번 MCP 서버를 만들면 어떤 호스트에서든 붙는다" 가 됐다. F&B 마케팅 자동화 관점에서도 Shopify · Meta Ads · Instagram · GA4 · Slack 같은 외부 시스템을 MCP 서버 한 번 작성으로 모든 에이전트에 공유 가능. 단 2026년 현재 미해결 영역은 SSO 통합 auth · 감사 로그 · 게이트웨이 정책 으로, 엔터프라이즈 채택의 핵심 과제로 남아 있다.[^thenewstack]

    1.2.3 Agent Skills — 프롬프트 자산의 코드화

    Anthropic이 2025-12-18 Agent Skills 오픈 스펙 을 공개했다.[^anthropic-skills] 폴더 하나에 SKILL.md (YAML frontmatter + Markdown 지시문) + 보조 스크립트/리소스를 담는 단순 포맷이고, 핵심은 staged loading — 메타데이터만 부팅 시 읽고, 실제 호출될 때만 본문이 컨텍스트에 들어가서 토큰 비용을 잡는 구조다. 2026년 3월 시점 32개 도구 (Gemini CLI · JetBrains Junie · AWS Kiro · Block Goose · Cursor · OpenCode 등)가 동일한 SKILL.md를 읽는다.[^venturebeat]

    왜 중요한가 — 그동안 사내에 흩어져 있던 "ChatGPT 프롬프트 모음.docx" , "노션 프롬프트 라이브러리" 같은 비공식 자산이 버전 관리 가능한 코드 디렉토리 가 된다. F&B 마케팅이라면 브랜드 톤 매뉴얼 / 신메뉴 출시 카피 SOP / Meta Ads 캠페인 셋업 절차 를 각각 skill 폴더로 묶으면, 같은 자산을 Claude Code · Cursor · Paperclip의 모든 에이전트가 똑같이 호출 가능.

    1.2.4 Coding Agent의 성숙 + SDK 가격 재편

    Claude Code SDK가 2026년 3월 Claude Agent SDK 로 개명되며 "코드 전용" 프레임이 떨어져 나갔다. 같은 SDK 위에서 PowerPoint · Excel · Word · PDF 용 pre-built skill이 함께 제공되고, Cursor · Aider · Goose · OpenCode 같은 third-party 코딩 에이전트들이 같은 SKILL.md 포맷을 공유한다.[^anthropic-sdk] 한편 2026년 6월 15일부터 Claude Agent SDK · claude -p · GitHub Actions의 subscription 토큰이 별도 $200/월 크레딧 버킷으로 분리 되어, 헤비 유저의 실효 비용이 12~175배까지 오르는 정책 변경이 진행 중이다.[^releasebot]

    왜 중요한가 — "코딩 에이전트 = 개발자 전용" 의 구도가 깨지고 있다. Excel · PDF · PPT skill을 가진 동일 SDK가 마케팅 · 기획 · 운영 시나리오로 들어오는 중이고, 동시에 가격 모델이 "API 종량제" 로 회귀하면서 운영 비용을 처음부터 설계 변수로 두는 cost-aware 아키텍처 가 필수가 됐다.

    1.2.5 관찰성·평가의 표준화 — OTel + LangSmith 라인

    2026년 3월 LangSmith가 OpenTelemetry full support를 추가하면서, Laminar · Langfuse · LangSmith · Phoenix가 모두 OTLP를 공통 수신 포맷 으로 받게 됐다. 즉 에이전트 trace가 벤더 종속 없이 이식 가능해진 첫 해다.[^braintrust][^agentmarketcap] LangChain 설문 기준 production 운영 팀의 89%가 observability를 도입 했고, 62%는 단계별 step · tool call 단위 trace를 본다.

    왜 중요한가 — 멀티 에이전트가 늘어날수록 "왜 이 캠페인 카피가 이렇게 나왔는지" 의 사후 추적성이 production의 사활을 가른다. LangChain 설문에서 production 진입을 가로막는 1위 이유가 "quality" (32%) 였는데, 관찰성 없는 품질 개선은 불가능하므로 OTel은 사실상 진입 요건이 되고 있다.

    1.3 F&B 마케팅 자동화 관점 — 시드 3개

    본격 적용 논의는 5장 — 여기선 시드만 던진다.

    1. 조직형 오케스트레이션의 자연스러움 — Paperclip식 org-chart + 예산·승인 라인 모델은 F&B 마케팅의 캠페인 단위 워크플로 + 브랜드 매니저 승인 구조와 mental model이 가장 잘 맞는다 (가설, Q&A에서 검증).
    2. MCP 서버 = 통합 ROI 최대 영역 — Meta Ads · GA4 · 인스타 DM · Shopify · POS · 배달앱을 MCP 서버로 한 번 감싸면, 카피라이팅 · 캠페인 분석 · CS 에이전트가 모두 같은 도구를 쓸 수 있다.
    3. Brand 톤 = SKILL.md 로 자산화 — 브랜드 가이드라인 · 금지어 · 페르소나를 Agent Skill로 패키징하면 Claude · Cursor · Paperclip 어디서든 동일 톤이 강제된다 — 흩어진 프롬프트 사이로 새는 일관성 문제의 구조적 해법.
