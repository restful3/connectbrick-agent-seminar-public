4-Way 패러다임 분류

패러다임 대표 핵심 unit governance
그래프형 LangGraph 노드(step) 엣지에 HITL
역할극형 CrewAI / AutoGen / Swarm 발언(turn) critic 역할
skill 중심 Deep Agents / Claude Agent SDK skill 호출 사용자 코드 가드
조직형 Paperclip 이슈·태스크 런타임 강제

본 4-way는 통용 분류를 발표용 의사결정 언어로 단순화한 프레임. 실제 운영은 시각 워크플로(n8n/Make/Zapier), 개발자용 에이전트 플랫폼(Google Antigravity), custom workflow가 섞인 하이브리드가 된다.

그래프형 + 역할극형

그래프형 (LangGraph) — 노드(step)와 엣지(transition)로 결정적 분기를 명시. HITL 체크포인트는 엣지에 삽입. 결정적 분기 + 승인 게이트가 많은 워크플로에 자연스럽다.

역할극형 (CrewAI, AutoGen) — 역할 + 대화 + 협상. 누가 누구에게 메시지를 보내는가의 런타임 합의. 발산적 브레인스토밍, 다관점 검토에 자연스럽다.

송태영 05 / 29
송태영Agentic AI Research

skill 중심 + 조직형

skill 중심 (Deep Agents, Claude Agent SDK) — 도구 라이브러리 + 메인 루프. SKILL.md 의 staged loading. 코딩, 문서 작성, RAG-heavy 작업에 자연스럽다.

조직형 (Paperclip) — 회사: org chart + goal + budget + governance. 이슈 단위로 작업이 흐르고 보고 라인이 위임을 강제한다. 캠페인 단위 deliverable + 승인 라인 + 예산 한도가 있는 워크플로에 자연스럽다. → 본 회차 deep dive (3장)

도메인 인터뷰 전에는 단정하지 않기

먼저 확인할 것:

  • 고객은 어떤 원천 자료를 이미 가지고 있는가?
  • 어떤 채널이 실제 전환·재방문·매출에 기여하는가?
  • 사람이 반드시 승인해야 하는 항목은 무엇인가?
  • 비개발 운영자가 이해하는 화면은 조직도인가, 시각 워크플로인가?

오늘의 안전한 결론:

  • Paperclip은 도메인 정답이 아니라 승인·예산·감사 구조 의 벤치마크
  • 적용 해법은 도메인 인터뷰 이후에 확정
