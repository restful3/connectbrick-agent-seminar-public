Section 02 · Frame

프레임워크는 패러다임이다

프레임워크 이름보다 먼저 봐야 할 것은 작업의 기본 단위가 step인지, turn인지, skill인지, issue인지입니다.

패러다임 대표 핵심 단위 흐름 표현 거버넌스
그래프형 LangGraph 노드(step) 상태 그래프 + 엣지 엣지에 HITL
역할극형 CrewAI / AutoGen 발언(turn) 역할 + 대화 critic 또는 외부 래퍼
skill 중심 Deep Agents / Claude Agent SDK skill 호출 메인 루프 + staged loading 사용자 코드 가드
조직형 Paperclip 이슈 / 태스크 조직도 + 위임 런타임 강제

이 4-way는 정답 분류표가 아니라, 커넥트브릭 업무를 어느 사고 방식으로 먼저 그릴지 정하는 발표용 판단 프레임입니다.

Section 03 · Case

왜 Paperclip을 보나

Paperclip은 에이전트를 더 똑똑하게 만드는 도구보다, 에이전트 팀을 회사처럼 운영하는 control plane에 가깝습니다.

핵심 은유
한 명의 employee가 아니라, 목표·조직도·이슈·승인·예산을 가진 company를 만든다.
관점 일반 프레임워크 Paperclip 사례
작업 단위 step, turn, tool call issue / task
협업 구조 그래프, 대화, 메인 루프 org chart / delegation
통제 방식 코드나 prompt에 삽입 approval / policy / budget

Paperclip 자체가 목적이 아니라, 조직형이 어떤 시스템 모델을 요구하는지 보기 위한 사례입니다.

Section 03 · Limit

Paperclip이 보장하지 않는 것

조직형 control plane은 멈출 자리를 만들어 주지만, 모델 출력의 사실성과 품질을 자동 보장하지는 않습니다.

강한 것 남는 문제
누가 어떤 이슈를 맡았는지 추적 결과가 사실인지 자동 보장하지 않음
승인 전 진행 차단 승인자가 대충 통과시키면 의미가 약해짐
예산 초과 시 중단 한 번의 고비용 호출은 adapter 단계 제한 필요
로그와 감사 추적 브랜드 톤·정확성은 별도 룰과 리뷰 필요

결론: Paperclip은 “안전한 답변 생성기”가 아니라 “멈출 수 있는 운영 구조”입니다.
